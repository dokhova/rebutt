## Поток данных

```
действие пользователя
  → обработчик из view (onClick="{{…}}")
  → метод App (src/app/App.js): меняет state, отправляет событие аналитики, пишет в store
  → setState → перерисовка в следующем микротаске
  → App.view() = shellView + view текущего экрана
  → шаблон экрана → DOM (morphdom обновляет только изменившееся)
```

Правила, которые держат код в порядке:

- **domain** не знает про DOM, state и сеть. Всё, что можно посчитать, считается там.
- **views** только готовят значения для шаблона: форматируют, выбирают классы, привязывают обработчики к методам App. Состояние не меняют.
- **App** — единственное место, где меняется состояние и отправляются события аналитики.
- **services** — единственное место, где есть `fetch`, Supabase, PostHog и `localStorage` (кроме кэша инсайтов в App).
- **Стили** — только классы из `src/styles`. Инлайн-стили в шаблонах — только для значений, вычисляемых на лету (высота столбика, цвет фона, размер компонента).

## Мини-рантайм шаблонов

`src/core/runtime.js` — около 200 строк, описание синтаксиса в шапке файла. Коротко:

```html
<div class="{{cls}}">{{text}}</div>
<button onClick="{{save}}">Сохранить</button>
<sc-if value="{{hasScore}}">…</sc-if>
<sc-for list="{{rings}}" as="r">{{r.label}}</sc-for>
<sc-include name="today"></sc-include>                  <!-- фрагмент из templates/screens -->
<sc-component name="Pebble" type="4" size="34"></sc-component>
```

В шаблоне только подстановки путей (`a.b.c`), без выражений: всю логику держим во view.
Каждый `setState` перестраивает виртуальное дерево и сравнивает его с DOM через morphdom. Для приложения такого размера этого достаточно; при росте можно перейти на Preact или Lit, а view-функции перенести почти без изменений.

## Хранение данных

- Записи дня (`log`) — объект `{ 'YYYY-MM-DD': { gut: [], meals: [], period, water } }`, формат описан в `src/domain/score.js`. `water` — жидкость за день в мл одним числом (таблица `water_days`, одна строка на день).
- Клетчатка за день не хранится отдельно: это сумма `fiber` по блюдам (`fiberOf`). Нет блюд — показываем «—».
- После онбординга всё сохраняется в `localStorage` (`gt_state_v1`) и параллельно в Supabase: каждая запись — отдельной строкой, профиль — upsert с задержкой 0,7 с.
- При запуске локальные и серверные записи объединяются по `id` (`store.mergeLogs`).
- Фото еды и фото к вопросам ИИ в базу не сохраняются: только результат разбора.
- Рост (`height`, см) и вес (`weight`, кг) — в профиле, по желанию, целыми числами (`profiles.height_cm`, `weight_kg`). Вне диапазона 120–230 см / 30–250 кг считаются не указанными. В аналитику уходит только факт, что поле заполнено (`has_height`, `has_weight`).
- На «+» тип и цвет стула видны сразу: выбор любого из них ставит «стул был». Запись о стуле хранит тип, симптомы, цвет (`color`) и стресс 0–10 (`stress`). Любую запись можно открыть из «Записей дня» и исправить или удалить.
- Без Supabase или в демо-режиме `supabase === null`, все функции store молча работают только локально.

## Серверные функции

| Эндпоинт | Вход | Выход |
|---|---|---|
| `POST /api/food` | `{ image?: dataURL, note?, previous?, context }` | `{ is_food, name, kcal, protein, fat, carbs, fiber, tone, tip }` |
| `POST /api/ask` | `{ question, image?, history?, context }` | `{ answer }` |
| `POST /api/insights` | `{ context }` | `{ tip_title, tip_text, noticed }` |

`context` строит `domain/ai-context.js`. Ответы модели приходят строго по JSON-схеме (structured outputs).

**Что ИИ знает о пользователе** (`buildAiContext`, для `/api/ask` и `/api/insights`):
- `profile` — возраст, пол, рост, вес, цели из онбординга и профиля (`goals`) и своими словами (`own_goal`), беременность, КОК, день и фаза цикла, личные ориентиры `daily_targets` (вода, клетчатка), дата начала. Имя не передаётся.
- `summary` — сводка за всё, что есть в дневнике (до 90 дней, которые загружает приложение): сколько дней с записями, типы стула, дни без стула, частые симптомы, средние показатель/стресс/вода/клетчатка, частые блюда.
- `days` — подробно каждый день с данными за последние 30 дней: стул (тип, цвет), симптомы, стресс, блюда с КБЖУ, клетчатка за день, жидкость, месячные, показатель.

Для `/api/food` — `foodContext`: профиль + что уже съедено и выпито сегодня, чтобы совет был про остаток дня.
Общие правила для всех ответов — `SAFETY` в `api/_lib/openai.js`: в том числе не оценивать вес и фигуру, не называть ИМТ и при цели «Похудеть» поддерживать только бережными привычками, без диет и подсчёта калорий.
Кэш инсайтов (`aiContextHash`) — хэш всего контекста: обновляется и при новой записи, и при изменении профиля.
Если Supabase настроен, запрос без валидного JWT пользователя получит 401. Лимит — `AI_RATE_LIMIT_PER_MIN` запросов в минуту на пользователя.

## Как добавить…

**Экран:** шаблон `templates/screens/x.html` → `views/x.js` → строка в `views/index.js` → `registerPartial('x', …)` в `main.js` → `<sc-if value="{{is.x}}">` в `templates/app.html` и флаг в `views/shell.js` → имя для аналитики в `SCREEN_EVENT_NAME` в `App.js`.

**Событие аналитики:** вызвать `track('name', {…})` в методе App и дописать строку в `docs/ANALYTICS.md`.

**Поле профиля:** `domain/profile.js` (`blankProfile`) → колонка в новой миграции `supabase/migrations/` → `profileToRow` и `rowToProfile` в `services/store.js`.

## Экраны поверх основных

Документ (`legal`), сохранённое блюдо (`meal`) и запись о стуле (`entry`) открываются поверх текущего экрана — состояние в `App.state.legal / mealEdit / entryEdit`. Порядок выбора — в `App.view()`, «Назад» — `App.back()`.

ИИ-помощник (`assistant`) — панель снизу, как в Whoop: открывается круглой кнопкой рядом с нижним меню, закрывается крестиком, тапом по затемнению или «Назад». Экран под ней не меняется. К вопросу можно приложить фото (сжимается в `services/image.js`, на сервере уходит в `OPENAI_VISION_MODEL`). Ответ показывается по предложению раз в `SENTENCE_DELAY_MS` (`App.revealAnswer`).

## Нормы и источники

Правило: в приложении нет чисел и советов без официального источника. Все источники — в `domain/sources.js`; рядом с каждой нормой стоит «?», который открывает карточку с объяснением и ссылкой (`partials/info-card.html`, `state.info`). Добавляешь норму или тип совета — добавь источник и карточку туда же.

`domain/targets.js` → `dailyTargets(profile)` — одно место, откуда берут числа плитки на главной, раздел «Жидкости» на «+», подсказки, карточки «?» и ИИ:
- **Клетчатка:** 25 г в день для всех взрослых — ВОЗ, 2023.
- **Вода:** вся вода за день (напитки + еда) — EFSA, 2010: женщины 2,0 л, мужчины 2,5 л, беременность +0,3 л; пол не указан — 2,0 л.

Рост и вес в формулах не участвуют: у ВОЗ и EFSA нет норм по весу. Они хранятся в профиле и уходят в контекст ИИ.

Где стоит «?»: плитки «Клетчатка» и «Жидкость» и показатель «Форма» на главной, заголовок «Что может помочь», «из N л» в «+» → «Жидкости», «Бристольская шкала: 3–4 — норма» в «+» → «Стул», строка «Нормы на день» в профиле.

Подсказки (`domain/suggestions.js`) — только из этих же рекомендаций: клетчатка (ВОЗ), жидкость (EFSA), движение, регулярная еда без спешки и время на отдых (NICE), поводы показаться врачу (NHS). ИИ получает то же правило в `SAFETY` (`api/_lib/openai.js`): только доказательные советы, без детоксов, «чисток», голодания, БАДов, трав и мифов.

## Главная («Сегодня»)

Сверху вниз:

1. **Шапка** — аватар (→ профиль), день и дата по центру, кнопка календаря справа. Календарь — нативный `<input type="date">` поверх иконки (`App.pickDay`), диапазон: от начала использования (или 90 дней назад) до сегодня.
2. **Дуга «Работа кишечника»** — нижняя полуокружность, SVG 350×300, центр (175, 115), радиус 155 (числа — в `views/today.js` → `ARC` и в шаблоне). Закрашено `idx` из 100 слева направо, светлый ползунок на конце, цвет и мягкое свечение за дугой — по тону дня (`TONE_COLOR`, в дни месячных — `cycle`). Тап → инсайты.
3. **Показатели дня** — минимально: подпись, цифра («1 раз», «2 тип», «68 %») и одна и та же тонкая полоска у всех пяти показателей — насколько день близок к ровному. Стул — раз из обычных 1–3, Форма — `form` из `score.js`, Комфорт — % по отмеченному самочувствию. Ниже плитки Клетчатка (г из `FIBER_GOAL_G`) и Жидкость (л из `WATER_GOAL_ML`). Цвет сегментов и полосок — тот же порог, что у показателя: ≥ 80 лайм, 62–79 шалфей, ниже — фиолетовый.
4. **Что может помочь** — совет ИИ на сегодня (если пришёл) + правила из `domain/suggestions.js`, максимум 3. Правила учитывают записи дня, ориентиры и цели: «Наладить стул» — напомнить о воде раньше; «Без вздутия» — есть без спешки, клетчатку добавлять понемногу; «Реакция на еду» — сфотографировать еду, если блюд ещё нет; «Похудеть» намеренно не даёт советов про еду и калории. Рядом с заголовком «?» — откуда подсказки и когда стоит показаться врачу. 
5. Карточка цикла, «Записи дня».

## «+» — три карточки над меню

«+» не открывает отдельный экран (`App.state.addSheet`):

1. `'pick'` — экран под ним затемняется и размывается, над меню всплывают три отдельные карточки в один ряд: **Стул**, **Питание**, **Жидкости** (все помещаются в ширину, появляются по очереди). «+» в меню поворачивается в «×» и закрывает выбор. Точка у названия — в разделе уже что-то заполнено; тогда над карточками есть «Сохранить».
2. `'stool' | 'food' | 'water'` — выбранная карточка открывает шторку с формой раздела (`templates/screens/add.html`, значения `views/add-entry.js`). «‹» возвращает к карточкам, черновик (`state.form`) при этом не теряется.

«Сохранить» сохраняет всё заполненное сразу и закрывает всё. Тап по затемнению, «×» или крестик в шторке закрывают, черновик остаётся до следующего открытия. «Назад» (и BackButton Telegram): из формы — к карточкам, из карточек — закрыть. Минус в «Жидкостях» может уменьшить и уже сохранённое за сегодня — чтобы исправить ошибку.

Разметка — `partials/add-sheet.html`; она стоит в `app.html` перед меню, чтобы меню с «×» оставалось поверх затемнения.
Значения (`VIEWS.add`) смешиваются со значениями экрана под ними в одном объекте (`App.view()`), поэтому имена ключей в `add-entry.js` не должны совпадать с ключами `today.js`, `insights.js`, `profile.js`.

Демо: `/?demo#add` открывает главную с уже показанными карточками.

## Еда

Фото и/или текстовое описание → `POST /api/food` → КБЖУ, клетчатка, тон для кишечника, совет (`domain/meal.js` нормализует ответ). «Уточнить» отправляет прошлый разбор + текст уточнения, ИИ пересчитывает. Сохранённое блюдо можно уточнить или удалить из «Записей дня». Фото живёт только в текущей сессии (blob-ссылка) — после перезапуска уточнение идёт по тексту.

## Правила интерфейса

- **Контраст.** Текст — не ниже 4.5:1 к фону (WCAG AA), рамки полей, чипов и чекбоксов — не ниже 3:1 (`--line-control`). Новые цвета проверять по этим порогам.
- **Шрифт.** Системный (SF Pro / Roboto / Segoe UI), без внешних шрифтов. Минимальный размер текста — 13px. Крупные цифры — тонкие (200), заголовки разделов главной — светлые 30px (300): лёгкость и воздух, как в референсе.
- **Цвет только для смысла.** Зелёный/фиолетовый — состояние кишечника, лайм — главное действие и выбор, красный — удаление. Фон — графитовый градиент `--bg-top → --bg-mid → --bg`, одинаковый на всех экранах. Единственное свечение — мягкий круг в цвете состояния за дугой на главной; других декоративных градиентов и текстур нет.
- **Числа честные.** Нет данных — спокойная подпись («не отмечено», «нет еды»), а не 0 и не «—». Пустой день на главной: вместо процента только «Пока нет записей», вместо трёх показателей стула — одна строка «Отметить» (сразу открывает раздел «Стул»); плитки клетчатки и жидкости открывают свои разделы.
- **Страница закреплена.** `html, body` — `position: fixed`, `overscroll-behavior: none`; прокручивается только `.screen`. Плюс `disableVerticalSwipes()` в Telegram — свайп вниз не сворачивает приложение.
- **Текст поверх картинки** — только светлый (`--ink`), не серый.
- **Бережный тон.** Мы не истина, а проводник. Никаких «опасно», «плохо», «нужно», «надо»: поддерживаем и предлагаем простой шаг («попробуй», «можно», «многим помогает»). У подсказок — «?» с пояснением, что это не диагноз. Тест в `tests/domain.test.js` проверяет подсказки на «надо/нужно/должен». То же правило — в промптах ИИ (`SAFETY` в `api/_lib/openai.js`).
- **Ползунки** (стресс) — `core/range.js`: пока палец на шкале, меняются только сам ползунок и подпись, состояние приложения — один раз, когда палец отпустили. Тап по любому месту шкалы сразу ставит значение; вертикальный жест остаётся прокруткой. В Telegram на каждый шаг — лёгкая вибрация (`hapticSelection`). Нативный `<input type="range">` внутри остаётся для клавиатуры и экранного диктора.
- **Клавиатура.** Пока в фокусе текстовое поле, нижнее меню скрыто (`state.keyboard`).

## Telegram Mini App

SDK инициализируется перед аналитикой (`src/services/telegram.js`). Старые клиенты получают только поддерживаемые вызовы SDK.

**Вход.** В Telegram клиент отправляет `Telegram.WebApp.initData` на `POST /api/auth/telegram`. Сервер проверяет подпись токеном бота (`api/_lib/telegram.js`), находит или создаёт пользователя Supabase с техническим email `tg<id>@users.rebutt.app` и возвращает сессию. Так данные привязаны к Telegram-аккаунту, а не к хранилищу WebView. Вне Telegram — анонимный вход Supabase.

**Загрузка.** Пока не известно, есть ли профиль на сервере, показывается экран загрузки (`booting`, не дольше 6 с) — чтобы вернувшийся пользователь не видел онбординг.

**ИИ.** Запросы к `/api/*` несут и JWT Supabase, и `X-Telegram-Init-Data`. Сервер принимает любой из них (`requireUser` в `api/_lib/openai.js`).

**Профиль.** Имя по умолчанию и аватар берутся из `initDataUnsafe.user` (аватар не сохраняется в базе).

**Назад.** Нативная BackButton видна, когда есть куда возвращаться: открыт документ, профиль или не первый шаг онбординга (`App.canGoBack` / `App.back`).

**На главный экран.** Модалка `partials/home-prompt.html` (`state.homePrompt` = `'ios'` / `'android'`) предлагает добавить ярлык через `addToHomeScreen()` (Bot API 8.0): Android добавляет сразу, iOS показывает подтверждение Telegram. Показывается один раз за запуск на «Сегодня», только в Telegram на телефоне, после первой записи и если `checkHomeScreenStatus` не ответил `added` (`App.maybeShowHomePrompt`). Ответ человека хранится в `localStorage` (`gt_home_prompt`): «Напомнить позже» — спросим через 3 дня, крестик или «Назад» — через 14, ярлык добавлен — больше не спрашиваем (`domain/home-prompt.js`). Посмотреть в браузере: `?demo#a2hs`.

**Документы** открываются внутри приложения (экран `legal`): текст берётся из `<main>` файлов `public/legal/*.html` (`src/services/legal.js`) и вставляется через привязку `html="{{…}}"`. Ссылки между документами тоже открываются внутри, остальные — через `openLink` / `openTelegramLink`.

**Экспорт.** CSV создаётся через Blob, отчёт — через окно печати; в Telegram WebView это ненадёжно, поэтому внутри Telegram показывается просьба открыть приложение в браузере.

**Диагностика.** `GET /api/health?openai=1` показывает, какие переменные окружения заданы, и проверяет ключ OpenAI.

## Фото блюд

- **Своё фото.** На «+ → Питание» и в чате ИИ — одна кнопка выбора файла: система сама предлагает камеру или галерею (на iOS). Отдельную кнопку камеры для Android убрали — в Telegram на Android она не срабатывала.
- **Без фото.** Если блюдо описано словами, после разбора КБЖУ `App.startMealArt` просит `/api/meal-image` нарисовать картинку. Пока рисует — заглушка «ИИ рисует картинку…»; можно сохранять, не дожидаясь: картинка допишется к сохранённому блюду (`attachArtToSaved`). На фото с пометкой «Картинка ИИ». В разбор ИИ картинка не уходит (`source === 'text'`).
- **Хранение.** При сохранении фото уменьшается до 720 px (`photoForStorage`) → IndexedDB (`services/photos.js`) → Supabase Storage `meal-photos/<user_id>/<meal_id>.jpg`, путь — `meals.photo_path`. При запуске фото берутся из IndexedDB, с сервера — по временным ссылкам (бакет приватный). Миграция — `20261025120000_meal_photos.sql`.
- **Где видно.** Миниатюра в «Записях дня» и крупное фото сверху в карточке блюда; без фото — плашка цвета оценки.

## День записи

«+» пишет в день, выбранный в календаре на главной (`App.entryDay`), — так можно дописать забытый день. В шапке шторки — «Вчера, 24 октября» и т. п. По умолчанию выбран сегодняшний день.
